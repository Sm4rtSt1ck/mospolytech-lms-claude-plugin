# unitask

TUI-канбан для JSON-файла с задачами (бывший task-viewer). Плагин `mospolytech-lms` ставит его сам: бинарник скачивается из релизов этого репозитория, команда `unitask` появляется в терминале, путь к `progress.json` прописывается в настройках. Задачи раскладываются по колонкам-статусам, их можно переносить между колонками и редактировать прямо в терминале. Все правки сразу сохраняются в файл.

## Сборка

Нужен Go той версии, что указана в `go.mod`.

```sh
go build -o unitask .                # текущая система
GOOS=windows GOARCH=amd64 CGO_ENABLED=0 go build -o unitask.exe .
GOOS=darwin  GOARCH=arm64 CGO_ENABLED=0 go build -o unitask-mac .
```

Релизы собирает GitHub Actions (`.github/workflows/unitask-release.yml`) по тегу `unitask-v<версия>`: Linux x86_64/aarch64, macOS x86_64/arm64, Windows x86_64.

## Запуск

```sh
unitask                       # файл из настроек
unitask путь/к/tasks.json
unitask -config другой-конфиг.json
unitask -get-file             # напечатать путь к файлу из настроек
unitask -set-file путь.json   # записать путь в настройки (остальные настройки не меняются)
unitask -version
```

При первом запуске программа предложит выбрать тему (тёмную или светлую) и, если путь к файлу не передан, попросит его указать.

Настройки лежат в `config.json` в папке настроек пользователя:

- Linux: `~/.config/unitask/`
- macOS: `~/Library/Application Support/unitask/`
- Windows: `%AppData%\unitask\`

Если там настроек нет, а есть старые от task-viewer (`task-viewer/config.json` в той же папке), они копируются при первом запуске. Другой путь к настройкам задаётся флагом `-config` или переменной `UNITASK_CONFIG`. Все параметры меняются в программе на экране настроек (`s`).

## Какие файлы понимает

Жёсткой структуры нет. Задачей считается любой объект внутри массива, если хотя бы у одного объекта в этом массиве есть поле статуса (по умолчанию `status`). Вложенность вокруг может быть любой. Группа задачи – поле `name` или `title` объекта, в котором лежит массив, а если их нет – путь в JSON. Пустые массивы с тем же ключом, что и найденные списки, тоже считаются списками задач, чтобы в них можно было добавлять задачи.

Порядок ключей и все поля, о которых программа не знает, сохраняются как есть.

Оформление известных полей:

| Поле | Как показывается |
|---|---|
| `status` | цветом статуса |
| `title`, `name`, `summary` | жирным |
| `deadline`, `due`, `due_date` | просрочено – красным, ≤ 3 дней – оранжевым |
| `*_at`, `*date`, `created`, `updated` | акцентным цветом |
| `type` | бирюзовым, известные коды – по-русски (`lab` → «лабораторная») |
| `kind` | «◆ событие» (акцентным цветом) или «задача» |
| `category`, `priority`, `tags` | бирюзовым |
| `id`, `uuid`, `key` | приглушённо |
| `notes`, `description`, `comment` | обычным текстом с переносом |
| любое другое | как есть, без оформления |

Цвета статусов: to-do – синий, in-progress – оранжевый, done – зелёный, cancelled – красный. Цвет подбирается по смыслу названия (`отменено`, `review`, `backlog` тоже получат свой цвет). Статусы из файла, которых нет в списке колонок, добавляются справа автоматически. Фон нигде не заливается (кроме полосы прогресса) – используется фон терминала.

При переносе задачи в колонку «выполнено» поле `done_at` (если оно есть у задачи) получает сегодняшнюю дату, а при переносе обратно обнуляется. Корневое поле `updated` (если оно есть) обновляется при каждом сохранении. Названия этих полей настраиваются.

Если файл поменяли снаружи, программа перечитает его сама (проверка раз в 5 секунд, только когда в программе нет несохранённого ввода: открытого редактора поля, окна ввода или выбора). Если внешнее изменение совпало с вашей правкой, она не перезапишет файл, а предложит выбор: `r` – перечитать, `W` – перезаписать.

## Предметы

Группа задач (предмет, проект) – объект, в котором лежит список задач. Её название берётся из поля `name` или `title`.

- `v` – список предметов (рядом с каждым – «выполнено/всего»). Выбранный предмет открывается на той же доске, отфильтрованной по нему; «Все предметы» возвращает общую доску.
- `F2` – переименовать предмет: в списке предметов, на доске предмета или в карточке задачи.
- `e` – карточка предмета: выезжает блоком над полосой прогресса и показывает все поля предмета (преподаватель, заметки и т.д.), кроме самого списка задач. Поля правятся так же, как в карточке задачи; `e` или `Esc` закрывает блок.
- Над доской – полоса прогресса: блоки to-do, in-progress, done и cancelled с процентами внутри, справа – процент выполненного (done + cancelled). На общей доске она по всем задачам, на доске предмета – только по нему. Это единственное место с цветной заливкой: без неё текст внутри блоков не показать.

## Карточка задачи

- Первая строка – предмет. `Enter` на ней (или `p`) открывает список предметов, чтобы перенести задачу. Внизу списка – «+ новый предмет…»: он создаётся по образцу существующих (те же поля, пустые значения) рядом с ними.
- Статус выбирается из списка колонок.
- Тип выбирается из списка: базовые типы из настроек (по умолчанию `lab` – лабораторная, `essay` – реферат, `diploma` – диплом, `other` – прочее) и все типы, которые уже встречаются в файле. Внизу – «+ новый тип…». Известные коды показываются по-русски, в файл пишется код.
- Остальные поля редактируются текстом.

## Семестры

Текущий семестр записан в корневом поле `semester` (например, `2026-autumn`), прошлые лежат в `archive.<семестр>` в том же виде, в каком были в корне. Программа показывает один семестр: по умолчанию текущий.

- `c` – список семестров: текущий и архивные. Выбор архивного открывает его записи (в шапке – «архив: …»); их можно смотреть и править.
- `[` / `]` – предыдущий / следующий семестр прямо с доски.
- «+ новый семестр…» в списке `c`: программа спросит название нового семестра (по умолчанию – следующий после текущего; если поля `semester` ещё нет, сначала спросит, как назвать текущий) и что делать с незакрытыми записями:
  - **перенести как долги** – копия каждой незакрытой записи попадает в новый семестр в тот же предмет (с пометкой «Долг <семестр>.» в конце `notes`), а в архиве запись становится `cancelled` с пометкой «Перенесено в <семестр> как долг.». Выбор один на все незакрытые записи сразу;
  - **оставить в архиве** – новый семестр начинается пустым.

  Все предметы текущего семестра уходят в архив с датой переноса `archived_at`. Новые предметы создаются через `n` → «+ новый предмет…» по образцу старых. Весь переход отменяется одним `u`.
- `d` в списке `c` – удалить семестр (с подтверждением; `u` возвращает):
  - **архивный** – удаляется целиком со всеми записями;
  - **текущий** – программа возвращается к последнему архивному семестру: его предметы встают на место, долги возвращаются вместо `cancelled`-записей (со статусом, который у них был в удаляемом семестре), пометки о переносе убираются. Записи, появившиеся в удаляемом семестре, по выбору переносятся в восстановленный семестр или удаляются. Единственный семестр удалить нельзя.

## Задачи и события

Запись с полем `"kind": "event"` – событие (контрольная, зачёт, мероприятие), остальные – задачи. На карточке событие помечено «◆ событие». `t` переключает, что показывать: задачи и события, только задачи или только события; полоса прогресса считается по тому же фильтру. Вид записи меняется в карточке (поле `kind` – выбор из двух). Название поля и значение для событий настраиваются.

## Новые задачи

`n` создаёт задачу: на доске предмета – сразу в нём, на общей доске – после выбора предмета (можно создать и новый). Поля берутся по образцу соседней задачи (в пустом предмете – любой задачи из файла), статус – по текущей колонке; при фильтре «только события» запись сразу становится событием. Сразу открывается ввод названия.

## Клавиши

Горячие клавиши работают и в русской раскладке.

Доска:

| Клавиша | Действие |
|---|---|
| `←↑↓→` / `hjkl` | выбор колонки и задачи |
| `Shift+←/→`, `<` `>`, `H` `L` | перенести задачу в соседнюю колонку |
| `1`–`9` | перенести в колонку с этим номером |
| `Enter` | открыть задачу |
| `n` | новая задача |
| `D` | удалить задачу |
| `/` | поиск по всем полям, `Esc` – сбросить |
| `v` | выбрать предмет |
| `t` | показывать: все / задачи / события |
| `F2` | переименовать предмет |
| `e` | карточка предмета (блок над прогрессом) |
| `c` | семестр: выбрать / создать новый |
| `[` `]` | предыдущий / следующий семестр |
| `o` | сортировка: по дедлайну / как в файле |
| `u` | отменить последнее изменение (история отмены живёт до выхода из программы и сбрасывается, когда файл перечитывается) |
| `W` | перезаписать файл, если он изменился снаружи одновременно с вашей правкой |
| `r` | перечитать файл |
| `s` | настройки |
| `q` | выход |

Карточка задачи:

| Клавиша | Действие |
|---|---|
| `↑↓` | выбор поля |
| `Enter` / `e` | изменить поле; статус, тип и вид (`kind`) – выбор из списка, остальное – текстом (`Enter` – сохранить, `Alt+Enter` / `Ctrl+J` – новая строка, `Esc` – отмена) |
| `p` | перенести в другой предмет |
| `F2` | переименовать предмет |
| `a` | добавить поле |
| `d` | удалить поле |
| `D` | удалить задачу |
| `Shift+←/→`, `<` `>` | сменить статус |
| `Esc` | назад |

Строковые поля редактируются как обычный текст. Числа, массивы и объекты – как JSON. В пустое поле (`null`) можно ввести и то и другое: корректный JSON сохранится значением, остальное – строкой.

## Тесты

```sh
go test ./...
UNITASK_SAMPLE=путь/к/своему.json go test ./...   # на своём файле (он копируется, оригинал не трогается)
```
