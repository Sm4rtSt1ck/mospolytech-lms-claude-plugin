# progress.json: справочник для агента

Файлы описывают учёт учёбы в `progress.json`, который ведут скиллы `homework-info` и `lms-lab`, и программу unitask, которая его показывает.

| Файл | О чём |
|---|---|
| [unitask.md](unitask.md) | Что за программа, как она читает файл, что в файле нельзя ломать, как сменить путь к файлу |
| [progress-format.md](progress-format.md) | Полный формат `progress.json`: корень, предметы, записи, поля |
| [kinds-and-types.md](kinds-and-types.md) | Задачи и события (`kind`), типы работ (`type`) и как их выбирать |
| [statuses.md](statuses.md) | Статусы записей, переходы между ними, `done_at` |
| [semesters.md](semesters.md) | Поле `semester`, архив прошлых семестров, когда начинать новый |

## Коротко

- Путь к `progress.json` сообщает хук плагина в начале сессии (контекст `mospolytech-lms: учёт задач — …`). По умолчанию это `<рабочая папка>/progress.json`; другой путь задаётся в `paths.progress_file` профиля. Если файла не было, хук создаёт пустой каркас текущего семестра.
- Файл правят двое: агент (скриптом или правкой JSON) и пользователь в unitask. Перед правкой всегда перечитывай файл – пользователь мог поменять его в программе минуту назад.
- Каждая запись – это задача (`"kind": "task"`) или событие (`"kind": "event"`), у неё есть тип (`type`) и статус (`status`).
- Статусы: `to-do`, `in-progress`, `done`, `cancelled`. Закрытыми считаются `done` и `cancelled`.
- Текущий семестр записан в корневом поле `semester`, прошлые семестры лежат в `archive` (см. [semesters.md](semesters.md)). Записи и предметы добавляй в текущий семестр, а не в архив.
- После любой правки обнови корневое поле `updated` на сегодняшнюю дату и проверь, что файл остался корректным JSON.
- Перенёс файл или узнал от пользователя, что он перенесён, – обнови `paths.progress_file` в `profile.yaml` и выполни `unitask -set-file "<новый путь>"`.

## Как править файл

- Пиши JSON с отступом 2 пробела и без экранирования кириллицы (`ensure_ascii=False` в Python, запускай `python3 -I`). Так файл остаётся в том же виде, в каком его сохраняет unitask, и в диффах видны только настоящие изменения.
- Не меняй порядок полей и не удаляй поля, которые не понимаешь: их мог добавить пользователь в программе.
- Перед крупной правкой (новый семестр, массовая смена статусов) сделай копию файла рядом или в scratchpad и скажи пользователю, где она лежит.
