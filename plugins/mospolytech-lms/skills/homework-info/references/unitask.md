# unitask

unitask (бывший unitask) – программа для терминала (TUI), которая показывает `progress.json` как канбан-доску и даёт пользователю править записи руками. Исходники – папка `unitask/` репозитория плагина (Go, Bubble Tea); плагин скачивает бинарник из релизов при старте сессии и добавляет команду `unitask` в терминал пользователя. Программа кроссплатформенная (Linux, macOS, Windows).

Агенту программу запускать не нужно: она интерактивная. Важно другое – понимать, как она читает файл, чтобы не сломать то, что видит пользователь.

## Что видит пользователь

- **Доска.** Колонки – статусы `to-do`, `in-progress`, `done`, `cancelled`. Если в файле встретится другой статус, программа добавит для него колонку справа.
- **Цвета.** to-do – синий, in-progress – оранжевый, done – зелёный, cancelled – красный. Просроченный дедлайн – красный, до дедлайна 3 дня или меньше – оранжевый.
- **Полоса прогресса над доской.** Доля записей в каждом статусе и справа процент выполненного: (`done` + `cancelled`) / все.
- **Выбор предмета (`v`).** Доска только по одному предмету, полоса прогресса тоже по нему.
- **Фильтр записей (`t`).** Задачи и события / только задачи / только события.
- **Карточка записи (`Enter`).** Все поля записи. Статус, тип и вид (`kind`) выбираются из списка. Запись можно перенести в другой предмет, в том числе в новый.
- **Переименование предмета (`F2`)** и карточка предмета (`e`) – блок над полосой прогресса с полями предмета.
- **Семестры (`c`, `[`, `]`).** Показывается только открытый семестр; архивные можно открыть и править; новый семестр создаётся и удаляется в программе (см. [semesters.md](semesters.md)).
- **Новая запись (`n`).** Поля берутся по образцу соседней записи того же предмета.

## Как программа читает файл

Жёсткой схемы у программы нет, она ищет записи по признакам:

- **Запись** – объект внутри массива, если хотя бы у одного объекта этого массива есть поле `status`. Поэтому массив `tasks` без единой записи со `status` программа не распознает. Пустой массив `tasks` распознаётся, если в файле есть другие непустые массивы `tasks`.
- **Предмет** – объект, в котором лежит такой массив. Название предмета берётся из его поля `name` (если `name` нет – из `title`).
- **Заголовок записи** – поле `title`, иначе `name`, иначе `id`.
- **Дедлайн** – поле `deadline` (также понимаются `due`, `due_date`). Даты в формате `ГГГГ-ММ-ДД`.
- **Событие** – запись с `"kind": "event"`. Запись без `kind` считается задачей.
- **Тип** – поле `type`. Известные коды показываются по-русски (см. [kinds-and-types.md](kinds-and-types.md)), в файл всегда пишется код.

Программа ищет записи по всему корню файла, кроме блока `archive`: он показывается только при выборе архивного семестра. Внутри `archive.<семестр>` структура та же, что в корне. Подробнее – [semesters.md](semesters.md).

## Что программа меняет в файле сама

- При переносе записи в `done` ставит `done_at` = сегодня, при переносе из `done` обратно ставит `done_at` = `null`. Делает это, только если у записи уже есть поле `done_at`.
- При каждом сохранении обновляет корневое `updated` на сегодня.
- При создании нового семестра переносит текущие предметы в `archive.<семестр>` (с `archived_at`), записывает `semester` после `updated` и, если пользователь выбрал, переносит незакрытые записи как долги.
- При создании нового предмета копирует поля существующего предмета с пустыми значениями, ставит `name` и пустой `tasks`. Ключ предмета в `subjects` получается транслитерацией названия (`Менеджмент` → `menedzhment`). Исключение – перенос долгов в новый семестр: там предмет создаётся под тем же ключом и со всеми полями (преподаватель, заметки) из архива.
- Сохраняет порядок полей и все поля, о которых не знает.
- Пишет файл с отступом 2 пробела, без экранирования кириллицы.

Если файл поменяли снаружи (например, агент), программа перечитает его сама (проверка раз в 5 секунд; пока пользователь что-то вводит – редактирует поле, выбирает из списка – перечитывание откладывается). Если внешняя правка совпала с правкой пользователя, программа не перезапишет файл молча, а предложит пользователю выбрать: перечитать или перезаписать. Поэтому агенту не нужно просить пользователя закрыть программу перед правкой.

## Что нельзя ломать

- Не переименовывай поля `status`, `kind`, `type`, `title`, `deadline`, `done_at`, `id`, а у предмета – `name` и `tasks`. Программа (и сам агент в следующий раз) опирается именно на эти имена.
- Не складывай записи в массив под другим ключом (например, `events`): массив без записей со `status` программа не увидит, а с ними – покажет как отдельный предмет-дубль. События лежат в том же `tasks`, что и задачи, и отличаются полем `kind`.
- Не пиши даты в другом формате (`21.11.2026`, `21 ноября`): программа не поймёт их как дедлайн и не подсветит просрочку.
- Не пиши в `type` русские названия («лабораторная»): программа сама показывает коды по-русски, а русское слово станет отдельным, «чужим» типом.

## Настройки программы

Настройки лежат в `~/.config/unitask/config.json` (на macOS – `~/Library/Application Support/unitask/`, на Windows – `%AppData%\unitask\`). Там путь к файлу, тема, список колонок и названия полей.

- **Путь к progress.json** прописывает плагин: при старте сессии, если у unitask файла нет или он не существует, туда записывается путь из `paths.progress_file` профиля. Выбор пользователя в самой программе плагин не перетирает.
- **Если ты перенёс progress.json** или пользователь сказал, что перенёс его, – обнови `paths.progress_file` в `profile.yaml` и выполни `unitask -set-file "<новый путь>"` (команда из `bin/` плагина, работает без терминала). `unitask -get-file` показывает текущий путь.
- Остальные настройки агенту менять не нужно: если пользователь просит что-то настроить, подскажи, что это делается в самой программе на экране настроек (`s`).
