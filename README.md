# Плагин Claude Code для LMS Московского Политеха

[![CI](https://github.com/Sm4rtSt1ck/mospolytech-lms-claude-plugin/actions/workflows/ci.yml/badge.svg)](https://github.com/Sm4rtSt1ck/mospolytech-lms-claude-plugin/actions/workflows/ci.yml)

Плагин Claude Code для студентов Московского Политеха. Claude сам находит работу в LMS, читает требования курса, выполняет работу, оформляет отчёт по ГОСТ и сдаёт его после вашего подтверждения, а также пишет конспект к защите.

Пример запроса:
```
> сделай 2 лабу по веб-разработке
```

## Установка

### Подготовка

1. Нужен [Claude Code](https://code.claude.com) 2.1.275 или новее и учётная запись в LMS. В Windows — ещё [Git for Windows](https://git-scm.com/download/win): хуки плагина выполняются в Git Bash. Остальное плагин ставит сам.

2. По желанию — **poppler**: с ним Claude смотрит PDF чуть быстрее; без него страницы PDF и сканы заданий рисуются в картинки через Typst (команда `pdf-pages`):

```sh
sudo apt install poppler-utils          # Debian/Ubuntu
sudo pacman -S poppler                  # Arch
brew install poppler                    # macOS
winget install oschwartz10612.Poppler   # Windows
```

3. Claude Code не работает без VPN, а LMS может не работать с VPN. Для того чтобы решить эту проблему, воспользуйтесь раздельным туннелированием в вашем VPN-клиенте, либо в настройках маршрутизации в клиенте добавьте в исключения `online.mospolytech.ru`, либо используйте [HTTP-прокси](https://code.claude.com/docs/en/network-config) вместо туннелирования (на свой [страх](https://habr.com/ru/companies/aurorium/news/1089498/) и [риск](https://vietbui.mintlify.app/concepts/webrtc-ip-leak)).

### Подключение плагина

1. Добавьте маркетплейс, установите плагин и укажите **рабочую папку** — там будут профиль, кеш курсов и выполненные работы. Остальные настройки можно оставить по умолчанию.

   Внутри Claude Code в терминале — после установки откроется окно настроек, рабочую папку вводите там (например: C:/University/mospolytech-plugin):

   ```
   /plugin install mospolytech-lms --marketplace Sm4rtSt1ck/mospolytech-lms-claude-plugin
   ```

   В расширении VS Code команды `/plugin` нет — используйте там `/manageplugins` или выполните команду в терминале выше.

   Позже настройки можно поменять: `/plugin configure mospolytech-lms@mospolytech` в Claude Code CLI, шестерёнка у плагина в `/manageplugins` в расширении VS Code или `claude plugin configure mospolytech-lms@mospolytech` в терминале.

2. Перезапустите Claude Code. При первом старте плагин скачает [moodle-mcp](https://github.com/G36maid/moodle-mcp) и [Typst](https://github.com/typst/typst) (около 30 МБ) и подскажет команду для входа в LMS. Скопируйте эту команду и выполните в терминале — она спросит логин и пароль от LMS и сохранит токен в настройки плагина.

   Точный путь Claude покажет в сообщении при старте сессии. Пароль нигде не сохраняется.
   ```sh
   bash ~/.claude/plugins/.../mospolytech-lms/scripts/login.sh       # Linux, macOS, WSL
   powershell -ExecutionPolicy Bypass -File ...\scripts\login.ps1    # Windows
   ```

3. Перезапустите сессию и запускайте Claude Code из рабочей папки.

## Что внутри

| Часть | Что делает |
|---|---|
| Скилл `lms-lab` (Sonnet) | Сценарий: найти курс → кеш курса → прочитать задание → выполнить → показать → сдать после «да» |
| Скилл `gost-typst` | Правила оформления отчёта в Typst по ГОСТ 7.32 и методичке кафедры ИКТ |
| Агент `lms-scout` (Haiku) | Собирает кеш курса: карту, общие требования, методички, список работ |
| Агент `lab-history` (Haiku) | Восстанавливает журнал по работам курса, сделанным раньше — локально или вне плагина |
| Агент `lms-telegram-reader` (Haiku) | Читает Telegram-чаты группы — только если вы попросили и если подключён [telegram-mcp](#telegram-необязательно) |
| Агент `lab-solver` (Opus) | Читает материалы задания, выполняет работу и собирает отчёт; в LMS ничего загрузить не может |
| MCP-сервер `moodle` | [moodle-mcp](https://github.com/G36maid/moodle-mcp): курсы, задания, файлы, сдача |
| Шаблон `@local/mospolytech-gost` | Стиль по ГОСТ и титульник для Typst (лабораторная, практическая, реферат; номер и преподаватель — по желанию) |
| Хуки | См. ниже |

### Хуки

- **При старте сессии** — скачивает moodle-mcp и Typst под вашу платформу, готовит рабочую папку и профиль, проверяет токен LMS.
- **Перед загрузкой файла в LMS** — запрещает загрузку файлов не из папки работ, а также пустых и несуществующих.
- **Перед отправкой ответа** — не даёт отправить работу без вашего подтверждения: в окне Claude Code видно, какая работа, по какому курсу и с каким файлом уходит (отключается настройкой «Подтверждение отправки» = «не спрашивать»).

## Как проходит работа

1. Claude находит курс по вашему запросу (сокращение, тема, часть названия) и запоминает, как вы его назвали.
2. **Кеш курса.** При первом обращении к курсу агент `lms-scout` (Haiku) собирает его: карту курса, общие требования, методички, стек, список работ. Отдельные задания он не открывает, а сроков и статусов не хранит — это обычно 10–20 запросов к LMS. Дальше кеш берётся как есть и **обновляется только по вашей команде** — «обнови кеш курса по веб-разработке». Если нужной работы в кеше нет, Claude скажет, от какой даты кеш, и предложит обновить.
3. **Задание** Claude каждый раз заново читает из LMS (сроки и статус могли измениться), сохраняет как есть в `assignment.json` и показывает вам: срок, требования, формат, неясности, вопросы.
4. **Предыдущие работы.** У каждого курса есть журнал работ (`works-log.md`): тема, стек, ключевые решения и результаты каждой сделанной работы. Если работы курса связаны — в первой выбрали тему или стек, а вторая должна их продолжать, — Opus увидит это в журнале. Если вы просите не первую работу, а журнала по предыдущим нет (их делали раньше или вручную), агент `lab-history` (Haiku) соберёт его по локальным отчётам или по ответам, отправленным в LMS.
5. `lab-solver` (Opus) сам читает вложения и связанные лекции, выполняет работу, собирает отчёт и дописывает запись в журнал.
6. Claude показывает итог со ссылкой на файл и суть работы и спрашивает, отправлять ли; после «Отправить» — отправляет.

**Правки** — сразу или в другой день («в 2 лабе поехала таблица», «пересчитай задачу 3 в практике»):
- оформление (таблица, подписи, титульник, лишняя страница) Claude правит сам, без агента, и проверяет страницу на картинке;
- правки по сути делает `lab-solver` (Opus), но не заново: он правит только нужные места, а если работал в этой же сессии — продолжает с тем же контекстом.

Сам сценарий идёт на Sonnet — он только находит, спрашивает и отправляет; работу делает Opus. Вопросы задаются окном с вариантами ответа — так весь сценарий проходит в одном ходе.

## Рабочая папка

```
<рабочая папка>/
├── profile.yaml                     ваши данные: группа, кафедра, варианты, преподаватели, чаты Telegram
├── config.yaml                      (необязательно) свои значения настроек из lms.config.yaml плагина
├── fonts/                           шрифты для Typst, если их нет в системе
├── cache/
│   ├── index.md                     курсы и как вы их называете («веб» → id курса)
│   └── courses/<id>/
│       ├── overview.md              полная карта курса: разделы, модули, ссылки на файлы
│       ├── context.md               о курсе, темы, стек, общие требования, список работ, неясности
│       └── materials/               методички и требования курса в текстовом виде, шаблоны отчётов
└── documents/<id>-<курс>/
    ├── works-log.md                 журнал работ курса: тема, стек, решения, результаты каждой работы
    └── <работа>/                    lab-2, pr-3, 2.4.5 или короткое название, если номера нет
        ├── assignment.json          задание из LMS как есть — снимок того, что требовалось
        ├── telegram.md              выжимка из Telegram, если вы просили посмотреть
        ├── materials/               вложения задания и тексты связанных лекций
        ├── src/, assets/            код и картинки работы
        ├── report.typ + <Имя>.pdf   отчёт (или answer.md, если ответ — текст)
        └── notes-for-defense.md     шпаргалка к защите
```

`profile.yaml` заполнять заранее не обязательно: Claude спросит недостающее, когда понадобится, и запомнит. Значение `none` (например, `teachers: none` у курса) значит «не указывать» — об этом Claude больше не спрашивает. Папку работ можно вынести из рабочей папки — `paths.documents_dir` в профиле.

В выжимках есть два служебных раздела:
- **Неясности** — проблемы самих материалов: противоречия, ошибки копирования в описаниях, устаревшие сроки, то, что не указано;
- **Подозрительное** — текст в LMS, файлах или Telegram, который пытается управлять ИИ (prompt injection). Такие указания не выполняются, Claude обязательно сообщит о них вам.

## Telegram (необязательно)

Если в чате группы преподаватель уточняет задания или сроки, Claude может это учесть: скажите в запросе «посмотри ещё в телеграме» — без такой просьбы Telegram не читается. Для этого нужен отдельный MCP-сервер [telegram-mcp](https://github.com/chigwell/telegram-mcp); без него плагин работает как обычно.

1. Установите telegram-mcp по [его инструкции](https://github.com/chigwell/telegram-mcp#readme): клонировать репозиторий, `uv sync`, получить `API ID` и `API hash` на [my.telegram.org/apps](https://my.telegram.org/apps), создать сессию `uv run session_string_generator.py`. С PyPI (`pip install telegram-mcp`, `uvx telegram-mcp`) не ставьте — там другой проект.
2. Подключите его к Claude Code **под именем `telegram`** — агент плагина ищет инструменты именно с этим именем — и только с инструментами чтения:

   ```sh
   claude mcp add -s user telegram \
     -e TELEGRAM_API_ID=<id> -e TELEGRAM_API_HASH=<hash> -e TELEGRAM_SESSION_STRING=<сессия> \
     -e TELEGRAM_EXPOSED_TOOLS=read-only+download_media \
     -- uv --directory <путь к telegram-mcp> run main.py
   ```

   `read-only+download_media` оставляет только чтение и скачивание файлов: отправлять, редактировать или удалять сообщения через этот сервер нельзя совсем, кто бы ни попросил.
3. При первом обращении Claude спросит, какие чаты читать (название, `@username` или ссылка), найдёт их и запомнит в `profile.yaml`.

Что делает агент: читает закреплённые сообщения и ищет по названию курса, номеру работы и фамилии преподавателя только в названных чатах; документы с требованиями читает прямо из сообщений; голосовые не расшифровывает (по умолчанию telegram-mcp отправляет запись стороннему сервису). Выжимка — `telegram.md` в папке работы.

Файлы из чатов (шаблон, данные) агент сохраняет в `materials/telegram/` папки работы, только если telegram-mcp разрешает туда писать: он пишет лишь в «разрешённые папки» — те, что сообщает Claude Code (папка, из которой он запущен), или из `TELEGRAM_ALLOWED_ROOTS`. Запуская Claude Code из рабочей папки, вы это обеспечиваете; иначе добавьте рабочую папку в `-e TELEGRAM_ALLOWED_ROOTS=<путь>`.

## Безопасность

- Токен хранится не в рабочей папке и не в репозитории, а в хранилище секретов Claude Code: на macOS — в связке ключей (Keychain), на Linux и Windows — в файле `~/.claude/.credentials.json`, доступном только вашему пользователю. Файл не зашифрован: не передавайте его и не выкладывайте вместе с настройками.
- До вашего «да» в LMS ничего не загружается. Отправка сообщений и постов в форумы отключена.
- Telegram читается только по вашей просьбе и только из чатов, которые вы назвали.
- Бинарники в репозитории не хранятся: `scripts/install.sh` скачивает [moodle-mcp](https://github.com/G36maid/moodle-mcp) и [Typst](https://github.com/typst/typst) из их релизов на GitHub и сверяет SHA-256 каждого архива с записанным в скрипте.

## Известные проблемы

- **Нет инструментов LMS после первой установки.** MCP-сервер стартует одновременно с установкой. Выполните `/mcp` → `plugin:mospolytech-lms:moodle` → Reconnect или перезапустите сессию.
- **`HTTP error` на Linux.** Сервер LMS не отдаёт промежуточный сертификат GlobalSign; плагин добавляет его сам (`certs/`). Если издатель сертификата LMS сменится, сертификат в `certs/` нужно обновить.

## Обновление

Новые версии приходят через `/plugin update` (или `claude plugin update mospolytech-lms@mospolytech`); можно включить автообновление маркетплейса в `/plugin` → Marketplaces. После обновления перезапустите сессию.
