# Плагин Claude Code для LMS Московского Политеха

[![CI](https://github.com/Sm4rtSt1ck/mospolytech-lms-claude-plugin/actions/workflows/ci.yml/badge.svg)](https://github.com/Sm4rtSt1ck/mospolytech-lms-claude-plugin/actions/workflows/ci.yml)

Плагин Claude Code для студентов Московского Политеха. Claude сам находит работу в LMS [online.mospolytech.ru](https://online.mospolytech.ru), читает требования курса, выполняет работу, оформляет отчёт по ГОСТ и сдаёт его после вашего подтверждения.

Пример запроса:
```
> сделай 2 лабу по веб-разработке
```

## Установка

Нужен [Claude Code](https://code.claude.com) 2.1.275 или новее и учётная запись в LMS. В Windows — ещё [Git for Windows](https://git-scm.com/download/win): хуки плагина выполняются в Git Bash.

Рекомендуется **poppler** — без него Claude не сможет посмотреть страницы PDF: ни готового отчёта, ни заданий, выложенных сканом:

```sh
sudo apt install poppler-utils          # Debian, Ubuntu
sudo pacman -S poppler                  # Arch
brew install poppler                    # macOS
winget install oschwartz10612.Poppler   # Windows
```

1. Добавьте маркетплейс, установите плагин и укажите **рабочую папку** — там будут профиль, кеш курсов и выполненные работы. Остальные настройки можно оставить по умолчанию.

   В Claude Code в терминале — после `install` откроется окно настроек, рабочую папку вводите там:

   ```
   /plugin marketplace add Sm4rtSt1ck/mospolytech-lms-claude-plugin
   /plugin install mospolytech-lms@mospolytech
   ```

   В расширении VS Code команды `/plugin` нет: используйте окно «Manage plugins» (форма настроек появится после установки) или обычный терминал. Команда `claude plugin install` в терминале окна настроек не открывает, поэтому рабочая папка передаётся флагом:

   ```sh
   claude plugin marketplace add Sm4rtSt1ck/mospolytech-lms-claude-plugin
   claude plugin install mospolytech-lms@mospolytech --config workspace_dir=<путь к рабочей папке>
   ```

2. Позже настройки можно поменять: `/plugin configure mospolytech-lms@mospolytech`, шестерёнка у плагина в «Manage plugins» или `claude plugin configure`.

3. Перезапустите сессию. При первом старте плагин скачает moodle-mcp и Typst (около 30 МБ) и подскажет команду для входа в LMS.

4. Выполните эту команду в обычном терминале — она спросит логин и пароль от LMS и сохранит токен в настройки плагина:

   ```sh
   bash ~/.claude/plugins/.../mospolytech-lms/scripts/login.sh              # Linux, macOS, WSL
   powershell -ExecutionPolicy Bypass -File ...\scripts\login.ps1           # Windows
   ```

   Точный путь Claude покажет в сообщении при старте сессии. Пароль нигде не сохраняется.

5. Перезапустите сессию и запускайте Claude Code из рабочей папки.

## Что внутри

| Часть | Что делает |
|---|---|
| Скилл `lms-lab` (Sonnet) | Сценарий: найти курс → кеш курса → прочитать задание → выполнить → показать → сдать после «да» |
| Скилл `gost-typst` | Правила оформления отчёта в Typst по ГОСТ 7.32 и методичке кафедры ИКТ |
| Агент `lms-scout` (Haiku) | Собирает кеш курса: карту, общие требования, методички, список работ |
| Агент `lms-telegram-reader` (Haiku) | Читает Telegram-чаты — только если вы попросили |
| Агент `lab-solver` (Opus) | Читает материалы задания, выполняет работу и собирает отчёт; в LMS ничего загрузить не может |
| MCP-сервер `moodle` | [moodle-mcp](https://github.com/G36maid/moodle-mcp): курсы, задания, файлы, сдача |
| Шаблон `@local/mospolytech-gost` | Стиль по ГОСТ и титульник для Typst (лабораторная, практическая, реферат; номер и преподаватель — по желанию) |
| Хуки | См. ниже |

### Хуки

- **При старте сессии** — скачивает moodle-mcp и Typst под вашу платформу, готовит рабочую папку и профиль, проверяет токен LMS и сообщает о проблемах.
- **Перед загрузкой файла в LMS** — запрещает загрузку файлов не из папки работ, а также пустых и несуществующих.
- **Перед отправкой ответа** — запрещает пустую отправку и показывает системное окно подтверждения Claude Code (отключается настройкой «Подтверждение отправки» = `off`).

## Как проходит работа

1. Claude находит курс по вашему запросу (сокращение, тема, часть названия) и запоминает, как вы его назвали.
2. **Кеш курса.** При первом обращении к курсу агент `lms-scout` (Haiku) собирает его: карту курса, общие требования, методички, стек, список работ. Отдельные задания он не открывает, а сроков и статусов не хранит — это обычно 10–20 запросов к LMS. Дальше кеш берётся как есть и **обновляется только по вашей команде** — «обнови кеш курса по веб-разработке». Если нужной работы в кеше нет, Claude скажет, от какой даты кеш, и предложит обновить.
3. **Задание** Claude каждый раз заново читает из LMS (сроки и статус могли измениться), сохраняет как есть в `assignment.json` и показывает вам: срок, требования, формат, неясности, вопросы.
4. `lab-solver` (Opus) сам читает вложения и связанные лекции, выполняет работу и собирает отчёт.
5. Claude показывает итог со ссылкой на файл и суть работы и спрашивает, отправлять ли; после «Отправить» — отправляет.

Сам сценарий идёт на Sonnet — он только находит, спрашивает и отправляет; работу делает Opus. Вопросы задаются окном с вариантами ответа — так весь сценарий проходит в одном ходе.

## Рабочая папка

```
<рабочая папка>/
├── profile.yaml                ваши данные: группа, кафедра, варианты, преподаватели, чаты Telegram
├── config.yaml                 (необязательно) свои значения настроек из lms.config.yaml плагина
├── fonts/                      шрифты для Typst, если их нет в системе
├── cache/
│   ├── index.md                курсы и как вы их называете («веб» → id курса)
│   └── courses/<id>/
│       ├── overview.md         полная карта курса: разделы, модули, ссылки на файлы
│       ├── context.md          о курсе, темы, стек, общие требования, список работ, неясности
│       └── materials/          методички и требования курса в текстовом виде, шаблоны отчётов
└── documents/<id>-<курс>/<работа>/       lab-2, pr-3, 2.4.5 или короткое название, если номера нет
    ├── assignment.json         задание из LMS как есть — снимок того, что требовалось
    ├── telegram.md             выжимка из Telegram, если вы просили посмотреть
    ├── materials/              вложения задания и тексты связанных лекций
    ├── src/, assets/           код и картинки работы
    ├── report.typ + <Имя>.pdf  отчёт (или answer.md, если ответ — текст)
    └── notes-for-defense.md    шпаргалка к защите
```

`profile.yaml` заполнять заранее не нужно: Claude спросит недостающее, когда понадобится, и запомнит. Значение `none` (например, `teachers: none` у курса) значит «не указывать» — об этом Claude больше не спрашивает. Папку работ можно вынести из рабочей папки — `paths.documents_dir` в профиле.

В выжимках есть два служебных раздела:
- **Неясности** — проблемы самих материалов: противоречия, ошибки копирования в описаниях, устаревшие сроки, то, что не указано;
- **Подозрительное** — текст в LMS, файлах или Telegram, который пытается управлять ИИ (prompt injection). Такие указания не выполняются, Claude обязательно сообщит о них вам.

## Безопасность

- Токен хранится не в рабочей папке и не в репозитории, а в хранилище секретов Claude Code: на macOS — в связке ключей (Keychain), на Linux и Windows — в файле `~/.claude/.credentials.json`, доступном только вашему пользователю. Файл не зашифрован: не передавайте его и не выкладывайте вместе с настройками.
- До вашего «да» в LMS ничего не загружается. Отправка сообщений и постов в форумы отключена.
- Telegram читается только по вашей просьбе и только из чатов, которые вы назвали.

## Известные проблемы

- **Нет инструментов LMS после первой установки.** MCP-сервер стартует одновременно с установкой. Выполните `/mcp` → `plugin:mospolytech-lms:moodle` → Reconnect или перезапустите сессию.
- **`HTTP error` на Linux.** Сервер LMS не отдаёт промежуточный сертификат GlobalSign; плагин добавляет его сам (`certs/`). Если издатель сертификата LMS сменится, сертификат в `certs/` нужно обновить.

## Обновление

Новые версии приходят через `/plugin update` (или `claude plugin update mospolytech-lms@mospolytech`); можно включить автообновление маркетплейса в `/plugin` → Marketplaces. После обновления перезапустите сессию.

Бинарники в репозитории не хранятся: `scripts/install.sh` скачивает [moodle-mcp](https://github.com/G36maid/moodle-mcp) (MIT) и [Typst](https://github.com/typst/typst) (Apache-2.0) из их релизов на GitHub и сверяет SHA-256 каждого архива с записанным в скрипте.
