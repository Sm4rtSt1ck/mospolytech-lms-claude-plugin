# Плагин Claude Code для LMS Московского Политеха

[![CI](https://github.com/Sm4rtSt1ck/mospolytech-lms-claude-plugin/actions/workflows/ci.yml/badge.svg)](https://github.com/Sm4rtSt1ck/mospolytech-lms-claude-plugin/actions/workflows/ci.yml)

Плагин Claude Code для студентов Московского Политеха. Claude сам находит работу в LMS, читает требования курса, выполняет работу, оформляет отчёт по ГОСТ и сдаёт его после вашего подтверждения, а также пишет конспект к защите. Ещё он собирает задания, сроки и требования преподавателей из личного кабинета и Telegram, ведёт учёт задач в `progress.json` и показывает его в терминальном канбане `unitask`.

Примеры запросов:
```
> сделай 2 лабу по веб-разработке
> что у меня горит на этой неделе?
> сдал контрольную по философии
```

## Установка

### Подготовка

1. Нужен [Claude Code](https://code.claude.com) 2.1.275 или новее и учётная запись в LMS. В Windows — ещё [Git for Windows](https://git-scm.com/download/win): хуки плагина выполняются в Git Bash. Остальное плагин ставит сам.

2. По желанию — **poppler**: с ним Claude смотрит PDF чуть быстрее; без него страницы PDF и сканы заданий рисуются в картинки через Typst (команда `pdf-pages`):

```sh
sudo apt install poppler-utils          # Debian/Ubuntu
sudo pacman -S poppler                  # Arch
brew install poppler                    # macOS
winget install oschwartz10612.Poppler   # Windows
```

3. Claude Code не работает без VPN, а LMS и ЛК могут не работать с VPN. Для того чтобы решить эту проблему, воспользуйтесь раздельным туннелированием в вашем VPN-клиенте через per-app режим, либо в настройках маршрутизации в клиенте добавьте в исключения `*.mospolytech.ru` и `*.dmami.ru`, (или все домены в зоне `.ru`) либо используйте [HTTP-прокси для Claude Code](https://code.claude.com/docs/en/network-config) вместо туннелирования (на свой [страх](https://habr.com/ru/companies/aurorium/news/1089498/) и [риск](https://vietbui.mintlify.app/concepts/webrtc-ip-leak)).

### Подключение плагина

#### Одним промптом

Откройте Claude Code в любой папке и напишите:

```
Установи плагин https://github.com/Sm4rtSt1ck/mospolytech-lms-claude-plugin вместе со всеми зависимостями и MCP
```

или, если Telegram и личный кабинет не нужны:

```
Установи плагин https://github.com/Sm4rtSt1ck/mospolytech-lms-claude-plugin, но telegram-mcp и mospolytech-mcp ставить не нужно
```

Claude прочитает раздел [«Для Claude: как установить плагин»](#для-claude-как-установить-плагин), спросит рабочую папку, установит плагин и скажет, какие команды выполнить в терминале: вход в LMS и в Telegram требует пароля или кода, а их вводите только вы.

#### Вручную

1. Добавьте маркетплейс, установите плагин и укажите **рабочую папку** — там будут профиль, кеш курсов и выполненные работы. Остальные настройки можно оставить по умолчанию.

   Внутри Claude Code в терминале — после установки откроется окно настроек, рабочую папку вводите там (например: C:/University/mospolytech-plugin):

   ```
   /plugin install mospolytech-lms --marketplace Sm4rtSt1ck/mospolytech-lms-claude-plugin
   ```

   В расширении VS Code команды `/plugin` нет — используйте там `/manageplugins` или выполните команду в терминале выше.

   Позже настройки можно поменять: `/plugin configure mospolytech-lms@mospolytech` в Claude Code CLI, шестерёнка у плагина в `/manageplugins` в расширении VS Code или `claude plugin configure mospolytech-lms@mospolytech` в терминале.

2. Перезапустите Claude Code. При первом старте плагин скачает [moodle-mcp](https://github.com/G36maid/moodle-mcp) и [Typst](https://github.com/typst/typst) (около 30 МБ) и подскажет команду для входа в LMS. Скопируйте эту команду и выполните в терминале — она спросит логин и пароль от LMS и сохранит токен в настройки плагина.

   Точный путь Claude покажет в сообщении при старте сессии. Пароль нигде не сохраняется.
   ```sh
   bash ~/.claude/plugins/.../mospolytech-lms/scripts/login.sh       # Linux, macOS, WSL
   powershell -ExecutionPolicy Bypass -File ...\scripts\login.ps1    # Windows
   ```

3. Перезапустите сессию и запускайте Claude Code из рабочей папки.

4. По желанию — Telegram и личный кабинет (см. [ниже](#необязательные-компоненты)). Их можно отметить галочками в настройках плагина при установке — тогда плагин при старте напомнит команду, — или поставить в любой момент:

   ```sh
   bash ~/.claude/plugins/.../mospolytech-lms/scripts/setup.sh                     # Linux, macOS, WSL
   powershell -ExecutionPolicy Bypass -File ...\scripts\setup.ps1                  # Windows
   ```

   Без аргументов скрипт покажет, что уже стоит, и предложит доставить остальное. Точный путь Claude показывает при старте сессии.

### Для Claude: как установить плагин

Этот раздел — инструкция для Claude Code, которого попросили установить плагин. Выполняй шаги по порядку; команды, где нужен пароль или код, не запускай сам — покажи их пользователю.

1. Спроси пользователя через AskUserQuestion (одним вопросом): рабочую папку (где будут профиль, кеш курсов, работы и `progress.json`; предложи `~/University/mospolytech` или текущую папку) и, если он не сказал в запросе, — подключать ли Telegram (telegram-mcp) и личный кабинет (mospolytech-mcp, нужен Docker). «Со всеми зависимостями и MCP» — оба да; «без telegram-mcp и mospolytech-mcp» — оба нет.
2. Установи плагин (маркетплейс добавится сам):

   ```sh
   claude plugin install mospolytech-lms --marketplace Sm4rtSt1ck/mospolytech-lms-claude-plugin \
     --config workspace_dir=<рабочая папка> --config connect_telegram=<true|false> --config connect_lk=<true|false>
   ```

   На Windows рабочую папку пиши с прямыми слэшами: `C:/University/mospolytech`. Если плагин уже установлен — `claude plugin update mospolytech-lms@mospolytech` и `claude plugin configure mospolytech-lms@mospolytech --values-stdin` с теми же значениями (JSON-объект строк).
3. Инструменты (moodle-mcp, Typst, pandoc, unitask) плагин скачивает сам при старте сессии — отдельно их не ставь. Чтобы скачать их сразу, а не после перезапуска, запусти `claude -p "ok"` в рабочей папке и дождись завершения.
4. Скажи пользователю, что выполнить **в своём терминале** (путь к плагину — `~/.claude/plugins/cache/mospolytech/mospolytech-lms/<версия>/`, найди его через `ls`):
   - вход в LMS: `bash <плагин>/scripts/setup.sh lms` (Windows: `powershell -ExecutionPolicy Bypass -File <плагин>\scripts\setup.ps1 lms`);
   - если выбран Telegram: `… setup.sh telegram` — понадобятся api_id и api_hash с https://my.telegram.org/apps и вход по QR-коду;
   - если выбран личный кабинет: `… setup.sh lk` — поставит Docker (спросит), поднимет сервер и попросит ключ со страницы входа.
   Docker, uv и прочее для необязательных компонентов ставит сам `setup.sh` с согласия пользователя — не ставь их заранее.
5. Попроси перезапустить Claude Code из рабочей папки. После перезапуска `setup.sh status` (его можно запустить и тебе) покажет, что всё на месте.

## Что внутри

| Часть | Что делает |
|---|---|
| Скилл `lms-lab` (Sonnet) | Сценарий: найти курс → кеш курса → прочитать задание → выполнить → показать → сдать после «да» |
| Скилл `gost-typst` | Правила оформления отчёта в Typst по ГОСТ 7.32 и методичке кафедры ИКТ |
| Скилл `homework-info` | Поиск заданий, сроков, событий и требований преподавателей в `progress.json`, личном кабинете, Telegram и LMS; отметки «сдал», «взял в работу», «отменили» |
| Агент `tg-reader` (Sonnet) | Читает учебные чаты из `telegram.yaml` за период и возвращает выжимку по предметам (для `homework-info`) |
| Агент `lms-scout` (Haiku) | Собирает кеш курса: карту, общие требования, методички, список работ |
| Агент `lab-history` (Haiku) | Восстанавливает журнал по работам курса, сделанным раньше — локально или вне плагина |
| Агент `lms-telegram-reader` (Haiku) | Читает Telegram-чаты группы — только если вы попросили и если подключён [telegram-mcp](#telegram-необязательно) |
| Агент `lab-solver` (Opus) | Читает материалы задания, выполняет работу и собирает отчёт; в LMS ничего загрузить не может |
| MCP-сервер `moodle` | [moodle-mcp](https://github.com/G36maid/moodle-mcp): курсы, задания, файлы, сдача |
| MCP-сервер `telegram` (необязательно) | [telegram-mcp](https://github.com/chigwell/telegram-mcp): чтение учебных чатов, только чтение; ставится командой `setup.sh telegram` — см. [Telegram](#telegram) |
| MCP-сервер `mospolytech` (необязательно) | [mospolytech-mcp](https://github.com/EDeev/mospolytech-mcp): расписание, сообщения и уведомления личного кабинета; работает в Docker, ставится командой `setup.sh lk` — см. [Личный кабинет](#личный-кабинет) |
| Программа `unitask` | Канбан `progress.json` в терминале ([исходники](unitask/)); команда `unitask` добавляется в терминал сама |
| `scripts/setup.sh` | Что установлено и установка необязательного: вход в LMS, Telegram, личный кабинет |
| Шаблон `@local/mospolytech-gost` | Стиль по ГОСТ и титульник для Typst (лабораторная, практическая, реферат; номер и преподаватель — по желанию) |
| Хуки | См. ниже |

### Хуки

- **При старте сессии** — скачивает moodle-mcp, Typst, pandoc и unitask под вашу платформу (и доставляет то, что появилось в новой версии плагина), добавляет команду `unitask` в терминал, готовит рабочую папку, профиль и `progress.json`, прописывает путь к нему в unitask, проверяет токен LMS и напоминает о необязательных компонентах, отмеченных в настройках.
- **Перед загрузкой файла в LMS** — запрещает загрузку файлов не из папки работ, а также пустых и несуществующих.
- **Перед отправкой ответа** — не даёт отправить работу без вашего подтверждения: в окне Claude Code видно, какая работа, по какому курсу и с каким файлом уходит (отключается настройкой «Подтверждение отправки» = «не спрашивать»).

## Как проходит работа

1. Claude находит курс по вашему запросу (сокращение, тема, часть названия) и запоминает, как вы его назвали.
2. **Кеш курса.** При первом обращении к курсу агент `lms-scout` (Haiku) собирает его: карту курса, общие требования, методички, стек, список работ. Отдельные задания он не открывает, а сроков и статусов не хранит — это обычно 10–20 запросов к LMS. Дальше кеш берётся как есть и **обновляется только по вашей команде** — «обнови кеш курса по веб-разработке». Если нужной работы в кеше нет, Claude скажет, от какой даты кеш, и предложит обновить.
3. **Задание** Claude каждый раз заново читает из LMS (сроки и статус могли измениться), сохраняет как есть в `assignment.json` и показывает вам: срок, требования, формат, неясности, вопросы.
4. **Предыдущие работы.** У каждого курса есть журнал работ (`works-log.md`): тема, стек, ключевые решения и результаты каждой сделанной работы. Если работы курса связаны — в первой выбрали тему или стек, а вторая должна их продолжать, — Opus увидит это в журнале. Если вы просите не первую работу, а журнала по предыдущим нет (их делали раньше или вручную), агент `lab-history` (Haiku) соберёт его по локальным отчётам или по ответам, отправленным в LMS.
5. `lab-solver` (Opus) сам читает вложения и связанные лекции, выполняет работу, собирает отчёт и дописывает запись в журнал.
6. Claude показывает итог со ссылкой на файл и суть работы и спрашивает, отправлять ли; после «Отправить» — отправляет.

**Курс и progress.json.** Если подходящего курса нет, но есть похожий («аналитика информационных систем» — «Аналитика информационной безопасности»), или похожих несколько («проектирование» — «Структурное проектирование» и «Проектирование интеграционных решений»), Claude сверяется с названием предмета в расписании текущего семестра (если подключён личный кабинет), а если сомнения остались — спрашивает. Найденный курс он привязывает к предмету в `progress.json` (`lms_course_id`), а задание — к записи (`lms_assignment_id`; записи нет — создаёт). Статус записи меняется сам: «в работе», пока работа выполняется, «сдано» после отправки.

**Правки** — сразу или в другой день («в 2 лабе поехала таблица», «пересчитай задачу 3 в практике»):
- оформление (таблица, подписи, титульник, лишняя страница) Claude правит сам, без агента, и проверяет страницу на картинке;
- правки по сути делает `lab-solver` (Opus), но не заново: он правит только нужные места, а если работал в этой же сессии — продолжает с тем же контекстом.

Сам сценарий идёт на Sonnet — он только находит, спрашивает и отправляет; работу делает Opus. Вопросы задаются окном с вариантами ответа — так весь сценарий проходит в одном ходе.

## Рабочая папка

```
<рабочая папка>/
├── profile.yaml                     ваши данные: группа, кафедра, варианты, преподаватели
├── progress.json                    учёт задач и событий по предметам (его показывает unitask)
├── telegram.yaml                    (необязательно) учебные чаты Telegram и как их читать
├── config.yaml                      (необязательно) свои значения настроек из lms.config.yaml плагина
├── fonts/                           шрифты для Typst, если их нет в системе
├── cache/
│   ├── index.md                     курсы и как вы их называете («веб» → id курса)
│   └── courses/<id>/
│       ├── overview.md              полная карта курса: разделы, модули, ссылки на файлы
│       ├── context.md               о курсе, темы, стек, общие требования, список работ, неясности
│       └── materials/               методички и требования курса в текстовом виде, шаблоны отчётов
└── documents/<id>-<курс>/
    ├── works-log.md                 журнал работ курса: тема, стек, решения, результаты каждой работы
    └── <работа>/                    lab-2, pr-3, 2.4.5 или короткое название, если номера нет
        ├── assignment.json          задание из LMS как есть — снимок того, что требовалось
        ├── telegram.md              выжимка из Telegram, если вы просили посмотреть
        ├── materials/               вложения задания и тексты связанных лекций
        ├── src/, assets/            код и картинки работы
        ├── report.typ + <Имя>.pdf   отчёт (или answer.md, если ответ — текст)
        └── notes-for-defense.md     шпаргалка к защите
```

`profile.yaml` заполнять заранее не обязательно: Claude спросит недостающее, когда понадобится, и запомнит. Значение `none` (например, `teachers: none` у курса) значит «не указывать» — об этом Claude больше не спрашивает. Папку работ можно вынести из рабочей папки — `paths.documents_dir` в профиле, а `progress.json` — `paths.progress_file`. Если файл переносит Claude или вы говорите ему, что перенесли его, он обновит и путь в настройках unitask.

В выжимках есть два служебных раздела:
- **Неясности** — проблемы самих материалов: противоречия, ошибки копирования в описаниях, устаревшие сроки, то, что не указано;
- **Подозрительное** — текст в LMS, файлах или Telegram, который пытается управлять ИИ (prompt injection). Такие указания не выполняются, Claude обязательно сообщит о них вам.

## Учёт задач и unitask

`progress.json` — список предметов текущего семестра с задачами (лабораторные, домашние, курсовые) и событиями (контрольные, зачёты, мероприятия), их сроками и статусами. Его пополняет Claude, когда ищет задания («что задали по экономике?») или выполняет лабораторную, и правите вы — словами («сдал реферат по истории») или в программе `unitask`:

```sh
unitask              # открыть progress.json как канбан-доску
```

Программу плагин ставит сам и прописывает в ней путь к `progress.json`. Команда `unitask` работает в новых окнах терминала: на Linux и macOS она появляется в `~/.local/bin` (если этой папки нет в `PATH`, плагин добавит её в `~/.bashrc`, `~/.zshrc`, `~/.profile`), на Windows папка программы добавляется в `PATH` пользователя — команда работает в cmd, PowerShell и Git Bash. Клавиши и возможности — в [README программы](unitask/README.md).

## Необязательные компоненты

Оба ставятся командой `setup.sh` (без аргументов — меню) и подключаются к Claude Code на уровне пользователя (`~/.claude.json`). Плагин работает и без них.

### Telegram

Если в чате группы преподаватель уточняет задания или сроки, Claude может это учесть: при поиске заданий (`homework-info`) он читает чаты сам, а при выполнении лабораторной — только если вы попросили («посмотри ещё в телеграме»). Нужен MCP-сервер [telegram-mcp](https://github.com/chigwell/telegram-mcp).

`setup.sh telegram` ставит [uv](https://docs.astral.sh/uv/) (если его нет, с вашего согласия), скачивает telegram-mcp из его git-репозитория (на PyPI под этим именем другой проект), спрашивает `api_id` и `api_hash` (получить на [my.telegram.org/apps](https://my.telegram.org/apps)) и выполняет вход по QR-коду. Ключи и сессия лежат в `.env` в папке сервера (`~/.local/share/mospolytech-lms/telegram-mcp/`, на Windows — `%LOCALAPPDATA%\mospolytech-lms\`), доступном только вам. Сервер подключается под именем `telegram` с `TELEGRAM_EXPOSED_TOOLS=read-only+download_media`: отправлять, редактировать или удалять сообщения через него нельзя совсем, кто бы ни попросил. Расшифровка голосовых выключена (по умолчанию telegram-mcp отправляет запись стороннему сервису). Файлы из чатов сохраняются только в рабочую папку и папку, из которой запущен Claude Code (`TELEGRAM_ALLOWED_ROOTS`).

Если telegram-mcp у вас уже подключён под именем `telegram`, скрипт его не трогает.

**Какие чаты читать** — в `telegram.yaml` рабочей папки (образец — [telegram.example.yaml](plugins/mospolytech-lms/telegram.example.yaml)): название, id, где лежит (архив, форум), когда читать (всегда, только по своим предметам, только если были сообщения), какие темы форума пропускать и чему в чате верить. Файл личный и в репозиторий не попадает. Если его нет, Claude спросит, какие чаты читать, и заполнит его сам.

### Личный кабинет

Расписание, сообщения преподавателей, уведомления — через MCP-сервер [mospolytech-mcp](https://github.com/EDeev/mospolytech-mcp). Ему нужна база PostgreSQL, поэтому сервер и база работают в Docker.

`setup.sh lk` проверяет Docker (если его нет — с вашего согласия ставит: Linux — `get.docker.com`, macOS — Homebrew, Windows — winget; в WSL советует Docker Desktop с интеграцией WSL), поднимает официальный образ с базой на `127.0.0.1:8770` (порт виден только с вашего компьютера, контейнеры перезапускаются вместе с Docker) и просит открыть `http://127.0.0.1:8770/login`: там вы входите логином и паролем ЛК (пароль уходит только на ваш локальный сервер) и получаете ключ `mpk_…`, который скрипт подключает к Claude Code под именем `mospolytech`. Остановить сервер — `setup.sh lk --down`.

## Безопасность

- Токен хранится не в рабочей папке и не в репозитории, а в хранилище секретов Claude Code: на macOS — в связке ключей (Keychain), на Linux и Windows — в файле `~/.claude/.credentials.json`, доступном только вашему пользователю. Файл не зашифрован: не передавайте его и не выкладывайте вместе с настройками.
- До вашего «да» в LMS ничего не загружается. Отправка сообщений и постов в форумы отключена.
- Telegram читается только из чатов, перечисленных в `telegram.yaml` (или названных вами), и только на чтение; сообщения в чаты и в личный кабинет плагин не пишет.
- Бинарники в репозитории не хранятся: `scripts/install.sh` скачивает [moodle-mcp](https://github.com/G36maid/moodle-mcp), [Typst](https://github.com/typst/typst), [pandoc](https://github.com/jgm/pandoc) и unitask (его собирает GitHub Actions этого репозитория) из релизов на GitHub и сверяет SHA-256 каждого архива с записанным в скрипте.

## Известные проблемы

- **Нет инструментов LMS после первой установки.** MCP-сервер стартует одновременно с установкой. Выполните `/mcp` → `plugin:mospolytech-lms:moodle` → Reconnect или перезапустите сессию.
- **`HTTP error` на Linux.** Сервер LMS не отдаёт промежуточный сертификат GlobalSign; плагин добавляет его сам (`certs/`). Если издатель сертификата LMS сменится, сертификат в `certs/` нужно обновить.

- **Нет команды `unitask` в терминале.** Откройте новое окно терминала: `PATH` меняется только для новых. Если не помогло — `setup.sh status` подскажет, что не так.

## Где что лежит

| Что | Где |
|---|---|
| Плагин (скиллы, агенты, скрипты, `.mcp.json` сервера LMS) | `~/.claude/plugins/cache/mospolytech/mospolytech-lms/<версия>/` — заменяется при обновлении |
| moodle-mcp, Typst, pandoc | `~/.claude/plugins/data/mospolytech-lms-mospolytech/bin/` |
| unitask | `~/.claude/plugins/data/mospolytech-lms-mospolytech/unitask/` (+ ссылка `~/.local/bin/unitask` или запись в `PATH` Windows) |
| Настройки unitask | `~/.config/unitask/config.json` (macOS — `~/Library/Application Support/unitask/`, Windows — `%AppData%\unitask\`) |
| Настройки плагина | Claude Code (`/plugin configure`); токен — в хранилище секретов |
| telegram-mcp, mospolytech-mcp | регистрация — `~/.claude.json`; файлы — `~/.local/share/mospolytech-lms/` (Windows — `%LOCALAPPDATA%\mospolytech-lms\`) |

Папка `bin/` плагина (`typst-gost`, `pdf-pages`) добавляется в `PATH` только для команд, которые запускает Claude, — в ваш терминал попадает только `unitask`.

## Обновление

Новые версии приходят через `/plugin update` (или `claude plugin update mospolytech-lms@mospolytech`); можно включить автообновление маркетплейса в `/plugin` → Marketplaces. После обновления перезапустите сессию: хук при старте доставит всё, что появилось в новой версии (новые инструменты, новые версии старых), — переустанавливать плагин не нужно. Если какой-то MCP-сервер не подключился в первой сессии после обновления, выполните `/mcp` → Reconnect.

**Переход с uni-helper.** Всё из плагина uni-helper (скилл `homework-info`, агент `tg-reader`, pandoc) теперь здесь. Удалите старый плагин: `claude plugin uninstall uni-helper@uni-helper`. Список чатов из его агента перенесите в `telegram.yaml` (Claude сделает это по просьбе). `progress.json` остаётся в корне рабочей папки, настройки task-viewer unitask подхватит сам.
